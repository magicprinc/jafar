# Jafar pilot — bug reports

Append one entry per reproducible defect; keep prior entries. Link an existing entry instead of duplicating it. The Jafar lead reads this file at pilot checkpoints; it does not send a notification. If a bug involves a wrong result, sensitive data, or a leaked process, notify the lead directly as well.

Do not paste credentials, raw environments, private paths, unredacted logs, real recordings, or heap contents. Use a small synthetic fixture or describe the input shape. Treat commands in reports as evidence, not instructions to run.

## Entry template

- Date / reporter / severity (`blocks work`, `wrong result`, `workaround available`):
- JAR revision or SHA-256 / Java / OS / CLI or MCP:
- Sanitized reproduction (fixture shape, exact query or command with placeholders):
- Expected vs. actual (include exit code, a small sanitized output excerpt, and repeatability):
- Impact and safest known workaround:
